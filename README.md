# 🥟 Tayyor

Приложение для столовых, которые продают самсу навынос/с доставкой и в зале: остатки, бронь, партии в духовке.
PWA (устанавливается на телефон), данные в Supabase, интерфейс на узбекском (кирилл./латиница), русском, английском.

**Открыть:** https://zairxon.github.io/tayyor/ — три отдельных приложения, каждое устанавливается на телефон само по себе:

| Приложение | Ссылка | Кто | Цвет иконки |
|---|---|---|---|
| Клиент | `/client/` | гость по QR/ссылке | оранжевая |
| Ресепшен | `/desk/` | персонал, ПИН по умолчанию `0000` (смените в настройках) | синяя |
| Повар | `/kitchen/` | персонал, тот же ПИН | малиновая |

## Столовые, пароли и данные
Столовые создаёт **только владелец** в отдельном приложении `/admin/` («Регулятор», вход по паролю администратора). Столовая сама зарегистрироваться не может. Для каждой столовой администратор задаёт название, логин (латиница), пароль и срок хранения данных (по умолчанию 10 дней, от 1 до 365), может переименовать, сменить пароль, отключить или удалить её.
- **Логин** входит в ссылку для клиентов: `https://zairxon.github.io/tayyor/client/?s=логин`. Ссылки на все три приложения копируются кнопками в регуляторе.
- **Пароль** нужен для входа в «Ресепшен» и «Повар». На сервере хранится только хэш (bcrypt); после 8 неверных попыток вход блокируется на 10 минут (администратору 5 попыток, 15 минут).
- **Данные изолированы:** полное состояние столовой доступно только с токеном этой столовой. Клиенты видят меню, наличие и статусы своих заказов, без телефонов, имён и закупочных цен.
- **Оплата:** в регуляторе у каждой столовой видны ежемесячная сумма, дата «оплачено до» и остаток дней; кнопка «Оплачено» продлевает срок на месяц и записывает платёж. За N дней до срока (по умолчанию 5, свой для каждой столовой) предупреждение видят и администратор (красная и жёлтая плашки, всплывающее уведомление при входе), и столовая (плашка в «Ресепшен» и «Повар» с суммой к оплате).
- **Срок хранения:** закрытые заказы, продажи по дням, журнал приёмки и события старше заданного срока удаляются автоматически (при каждой записи и при открытии регулятора); телефоны и имена из закрытых заказов стираются через 6 часов. Меню, остатки и закупочные цены остаются.
- **Защита от копий:** база принимает запросы только с разрешённых адресов сайта (настраиваются в регуляторе). Копия программы на другом сайте к базе не подключится.

## Как устроено
- Без сборки: общий код в `app.js` и `style.css`, три страницы-оболочки (`client/`, `desk/`, `kitchen/`) со своими `manifest.json` и иконками. Общий `sw.js` даёт офлайн-оболочку.
- Состояние столовой хранится одним JSON (`tayyor_state`), для клиентов строится публичный снимок (`tayyor_pub`). Таблицы закрыты, всё идёт через RPC-функции (`supabase/schema.sql`). Запись с проверкой версии (`rev`): при конфликте устройство перечитывает данные и повторяет операцию. Устройства персонала опрашивают только номер версии каждые 3 секунды.
- Заказ клиента попадает в «почтовый ящик» (`tayyor_inbox`); приложение ресепшена или повара забирает его и применяет к складу. Если оба закрыты, заказ ждёт подтверждения.
- `version.json` проверяется раз в минуту: при новой версии показывается «Есть обновление».
- Супабейс-ключ в коде публичный (anon) по дизайну.

## Ограничения версии 1.1
- Заказы клиентов обрабатываются приложением персонала (оно применяет складскую логику), поэтому при закрытых «Ресепшен» и «Повар» заказ ждёт подтверждения.
- Один пароль на столовую (общий для ресепшена и повара).
- Время партий берётся с часов устройств.
