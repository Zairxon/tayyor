# 🥟 Tayyor

Приложение для столовых, которые продают самсу навынос/с доставкой и в зале: остатки, бронь, партии в духовке.
PWA (устанавливается на телефон), данные в Supabase, интерфейс на узбекском (кирилл./латиница), русском, английском.

**Открыть:** https://zairxon.github.io/tayyor/ — три отдельных приложения, каждое устанавливается на телефон само по себе:

| Приложение | Ссылка | Кто | Цвет иконки |
|---|---|---|---|
| Клиент | `/client/` | гость по QR/ссылке | оранжевая |
| Ресепшен | `/desk/` | персонал, ПИН по умолчанию `0000` (смените в настройках) | синяя |
| Повар | `/kitchen/` | персонал, тот же ПИН | малиновая |

## Столовые, пароли и данные
Каждая столовая сама создаёт себя: в приложении «Ресепшен» → «Создать столовую» (название, код латиницей, пароль). Дальше:
- **Код** (например `samsa-aka`) входит в ссылку для клиентов: `https://zairxon.github.io/tayyor/client/?s=samsa-aka`. Ссылка и QR есть в «Настройки».
- **Пароль** нужен для входа в «Ресепшен» и «Повар». Хранится на сервере только в виде хэша (bcrypt). После 8 неверных попыток вход блокируется на 10 минут.
- **Данные изолированы:** полное состояние столовой доступно только с токеном входа этой столовой. Клиенты видят только меню, наличие и статусы своих заказов, без телефонов, имён и закупочных цен.
- Название столовой и пароль меняются в «Настройки».

## Как устроено
- Без сборки: общий код в `app.js` и `style.css`, три страницы-оболочки (`client/`, `desk/`, `kitchen/`) со своими `manifest.json` и иконками. Общий `sw.js` даёт офлайн-оболочку.
- Состояние столовой хранится одним JSON (`tayyor_state`), для клиентов строится публичный снимок (`tayyor_pub`). Таблицы закрыты, всё идёт через RPC-функции (`supabase/schema.sql`). Запись с проверкой версии (`rev`): при конфликте устройство перечитывает данные и повторяет операцию. Устройства персонала опрашивают только номер версии каждые 3 секунды.
- Заказ клиента попадает в «почтовый ящик» (`tayyor_inbox`); приложение ресепшена или повара забирает его и применяет к складу. Если оба закрыты, заказ ждёт подтверждения.
- `version.json` проверяется раз в минуту: при новой версии показывается «Есть обновление».
- Супабейс-ключ в коде публичный (anon) по дизайну.

## Ограничения версии 1.1
- Заказы клиентов обрабатываются приложением персонала (оно применяет складскую логику), поэтому при закрытых «Ресепшен» и «Повар» заказ ждёт подтверждения.
- Один пароль на столовую (общий для ресепшена и повара).
- Время партий берётся с часов устройств.
